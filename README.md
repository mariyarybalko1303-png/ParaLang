# 🌌 Мова програмування ParaLang (v26)
**ParaLang** — це спеціалізована навчальна мова програмування, створена для глибокого вивчення та інтерактивної візуалізації концепцій паралельного, конкурентного та розподіленого програмування. 

Цей інструмент дозволяє студентам практично опановувати найскладніші паралельні парадигми (OpenMP, MPI, Pthreads, STM, CUDA GPGPU, Actor Model) в єдиному уніфікованому та безпечному середовищі, не потребуючи складного налаштування локального системного ПЗ (на кшталт GCC, CUDA SDK чи MS-MPI).

## 🚀 Основні можливості та парадигми ParaLang (v26)

### 1. 🌌 Квантовий Мультиблок (`multiverse`) — *НОВА ФІЧА v26!*
Ексклюзивна фіча ParaLang для автоматичного виявлення **стану перегонів (data races)** та **взаємних блокувань (deadlocks)** шляхом симуляції квантових альтернативних всесвітів.
*   **Синтаксис:** `multiverse(N) { ... }`
*   **Принцип роботи:** Інтерпретатор копіює стан пам'яті та створює `N` паралельних всесвітів. Завдяки вбудованому хаотичному планувальнику (Chaos Scheduler) виконання операцій у кожному всесвіті штучно піддається мікросекундним рандомним затримкам.
*   **Результат:** Наприкінці виводиться детальний аналітичний звіт. Якщо всесвіти прийшли до різних фінальних станів або зависли — система видає детальне попередження про недетермінованість коду та підказує шляхи вирішення.

### 2. 🐢 Модель акторів (Actor Model) & канали (CSP)
*   **Канали:** Створення буферизованих та небуферизованих каналів комунікації (стиль Go):
    ```rust
    ch = channel(5);
    spawn {
        x = <- ch;
        print("Отримано з каналу:", x);
    }
    ch <- 100;
    ```
*   **Актори:** Ізольовані об'єкти зі своїм станом та поштовою скринькою (стиль Erlang/Elixir):
    ```rust
    actor PingPong {
        counter = 0
        receive(msg) {
            counter = counter + 1;
            print("Актор отримав:", msg, "Лічильник:", counter);
        }
    }
    p = PingPong();
    p <- "Hello";
    ```

### 3. 🧵 POSIX Threads (Pthreads)
Низькорівневе керування потоками та класичними примітивами синхронізації:
*   Створення та очікування потоків: `pthread_create()`, `pthread_join()`.
*   М'ютекси (Mutexes): `pthread_mutex_init()`, `pthread_mutex_lock()`, `pthread_mutex_unlock()`.
*   Рекурсивні м'ютекси: `pthread_recursive_mutex_init()`.
*   Умовні змінні (Condition Variables): `pthread_cond_init()`, `pthread_cond_wait()`, `pthread_cond_signal()`.
*   Семафори (Semaphores): `sem_init()`, `sem_wait()`, `sem_post()`.
*   Спінлоки (Spinlocks): `spinlock_init()`, `spinlock_lock()`, `spinlock_unlock()`.
*   Блокування читання-запису (Read-Write Locks): `pthread_rwlock_init()`, `pthread_rwlock_rdlock()`, `pthread_rwlock_wrlock()`, `pthread_rwlock_unlock()`.

### 4. 🔗 Транзакційна пам'ять (Software Transactional Memory — STM)
Альтернатива класичному синхронізаційному блокуванню (стиль Haskell). Дозволяє виконувати операції з пам'яттю оптимістично та атомарно:
*   Транзакційні змінні: `tvar(initial_value)`.
*   Читання та запис: `read_tvar()`, `write_tvar()`.
*   Атомарні транзакційні блоки: `atomically { ... }`.
*   Механізм відкату та повтору транзакцій при конфліктах: `retry;`.

### 5. 🔥 Стандарти OpenMP (від 1.0 до 5.0+)
Високорівневе розпаралелювання циклів та блоків на багатоядерних процесорах:
*   Паралельний цикл: `pfor k = 1 to 10 { ... }`.
*   Критичні секції: `critical { ... }` (OpenMP 1.0).
*   Атомарні інструкції: `omp_atomic { ... }` (OpenMP 2.0).
*   Одиночне виконання: `omp_single { ... }` та виконання майстер-потоком: `omp_master { ... }`.
*   Асинхронне виконання завдань (Task-based): `omp_task { ... }` та бар'єр синхронізації тасків `omp_taskwait;` (OpenMP 3.0/5.0).
*   Системні функції: `omp_get_thread_num()`, `omp_get_num_threads()`, `omp_get_wtime()`.

### 6. 🌐 Розподілені системи (Message Passing Interface — MPI)
Емуляція розподіленої системи з багатьох обчислювальних вузлів (процесів):
*   Ініціалізація MPI-сесії: `mpi_run(size) { ... }`.
*   Локальні змінні вузла: `rank` (ідентифікатор вузла від `0` до `size-1`) та `size` (загальна кількість вузлів).
*   Комунікація точка-точка (Point-to-Point): `mpi_send(dest_rank, value)`, `mpi_recv(source_rank)`.
*   Колективні операції: розсилка `mpi_bcast(root_rank, value)` та бар'єр `mpi_barrier()`.

### 7. 🏎️ Масово-паралельні обчислення (CUDA GPGPU)
Моделювання роботи графічного прискорювача без використання апаратного GPU:
*   Запуск GPU-ядер: `cuda_run(grid_dim, block_dim, kernel_function, input_array)`.
*   Вбудовані змінні всередині ядра: `threadIdx`, `blockIdx`, `blockDim`, `gridDim`.

### 8. 🧮 Допоміжні та вбудовані бібліотеки
*   `pmap(array, function)` — справжнє багатоядерне паралельне відображення масиву, яке використовує пул процесів Python (`ProcessPoolExecutor`).
*   `trace(entity)` — інтерактивна візуалізація поточного стану каналу чи актора (ємність, черга повідомлень, заблоковані відправники/отримувачі).
*   `timer()` — вбудований хронометр для заміру точного часу виконання алгоритмів.
*   `to_cpp(code_str)` та `to_go(code_str)` — автоматична трансляція коду ParaLang у чистий код на C++ (із OpenMP та `std::thread`) або Go (з горутинами та каналами).

## 🎓 Приклад програми: Обчислення числа Pi методом Монте-Карло

Паралельний алгоритм Монте-Карло з використанням високопродуктивного паралельного циклу `pfor` та атомарного накопичення результату:

```rust
print("Запуск обчислення Pi паралельно...");
total_points = 1000;
inside_points = 0;

start_time = omp_get_wtime();

pfor i = 1 to total_points {
    x = random();
    y = random();
    distance = x * x + y * y;
    if distance < 1.0 {
        omp_atomic {
            inside_points = inside_points + 1;
        }
    }
}

pi = 4.0 * inside_points / total_points;
end_time = omp_get_wtime();
elapsed = end_time - start_time;

print("Обчислене Pi:", pi);
print("Час виконання:", elapsed, "сек.");
```
